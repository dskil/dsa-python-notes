# Как решать задачи (инструкция для новичка)

Этот файл — для того, кто открыл репозиторий и хочет **порешать задачи**,
а не разбираться в устройстве проекта. Тут по шагам: что запускать,
как читать вывод и что делать, когда тест красный.

Не важно, какая у тебя система — команды ниже одинаковые в **Git Bash**,
**PowerShell** и **терминале Linux/macOS**. Различия только в одном:
как перейти в папку проекта (см. шаг 1).

---

## Шаг 0. Что нужно

- **Python 3.10 или новее.** Проверить:
  ```bash
  python --version
  ```
  Если выдаёт `Python 3.12.7` или похожее — всё нормально.
  Если пишет `command not found` — установи Python с python.org и перезапусти терминал.

- **git** — чтобы забрать репозиторий (или просто скачай ZIP с GitHub).

---

## Шаг 1. Забрать проект и зайти в папку

**Если репозиторий уже есть на компьютере** — просто перейди в него:

```bash
# Git Bash (важно: прямые слэши!)
cd /d/codes/dsa-python-notes

# PowerShell
cd D:\codes\dsa-python-notes
```

> Почему в Git Bash `/d/...`, а не `D:\...`: обратный слэш `\` в Git Bash —
> это спецсимвол экранирования, он «съедает» следующую букву. Путь `D:\codes`
> там превращается в `D:codes'`. Поэтому папки пиши через `/`:
> диск `D:` → `/d/`, диск `C:` → `/c/`. Проверить, на каком ты диске:
> `ls /` в Git Bash покажет `c`, `d`. Это и есть «корни» дисков.

**Если проекта ещё нет:**

```bash
git clone https://github.com/dskil/dsa-python-notes.git
cd dsa-python-notes
```

Проверка, что ты в нужной папке — команда `ls` должна показать файлы
`README.md`, папки `solutions`, `tests`, `src`.

---

## Шаг 2. Установить инструменты (один раз)

```bash
pip install -r requirements-dev.txt
```

Это поставит **pytest** (запускает тесты) и **ruff** (проверяет стиль).
Если `pip` не найден — попробуй `python -m pip install -r requirements-dev.txt`.

Хочешь пользоваться короткой командой `dsa-trainer` — поставь проект:

```bash
pip install -e .
```

Без этого тоже можно — тогда команды пишутся как `python -m dsa_trainer ...`
(и перед этим в Git Bash надо выполнить `export PYTHONPATH=src`).

---

## Шаг 3. Посмотреть, какие задачи есть

```bash
dsa-trainer list
```

Выводится каталог по темам, например:

```text
Рекурсия
--------
  [✓] 31  Факториал
  [ ] 32  Фибоначчи (наивная рекурсия)
  [.] 33  Сумма цифр числа
```

Что значит квадратик в начале строки:

| Знак | Что это | Делать |
|---|---|---|
| `[✓]` | ты уже решил эту задачу в этот раз | можно перерешать |
| `[.]` | решение в репозитории есть (эталон) | запускай `run`, тесты пройдут |
| `[ ]` | решения нет, это твоя задача | открывай файл и пиши код |

Полезные варианты:

```bash
dsa-trainer list --todo            # только `[ ]` — что решать
dsa-trainer list --topic "Числа"   # только одна тема
dsa-trainer show 33                # прочитать условие задачи №33
```

`dsa-trainer show 33` печатает текст задачи: что должна делать функция,
какие у неё аргументы, что возвращать и какие ошибки бросать.

---

## Шаг 4. Запустить тест задачи (главная команда)

Самый простой путь — одна команда, которая показывает условие и сразу
прогоняет тесты:

```bash
python tools/start.py 33        # задача №33
python tools/start.py           # первая нерешённая
python tools/start.py --list    # что есть и что решено
```

Скрипт печатает три блока: **условие**, **где писать код** и **что будет,
когда запустишь тест**. В конце — зелёное «ВСЁ ЗЕЛЁНОЕ» или красное
«КРАСНЫЙ, поправь функцию».

Эквивалент через CLI:

```bash
dsa-trainer run 33
```

Это запускает **все тесты именно этой задачи**. Если тесты прошли, в конце
будет строка:

```text
15 passed in 0.16s

Задача №33 решена ✓ (Сумма цифр числа)
```

Если ты не устанавливал пакет, то же самое через pytest напрямую:

```bash
python -m pytest tests/test_recursion_33.py -v
```

Ну и **все** задачи сразу (проверка «ничего не сломал»):

```bash
python -m pytest -q
```

## Шаг 5. Как читать вывод тестов

pytest выводит строчки вида:

```text
tests/test_recursion_33.py::test_matches_reference PASSED     [ 50%]
tests/test_recursion_33.py::test_digit_sum[-1] FAILED         [ 75%]
```

- `PASSED` — тест прошёл, всё хорошо.
- `FAILED` — тест упал, **и ниже pytest напишет почему**.
- `SKIPPED` — тест пропущен (например, не установлена библиотека Pillow).
- `[ 50%]` — это просто прогресс-бар, сколько тестов уже выполнено.

При `FAILED` самое важное — блок с ошибкой. Читай его **сверху вниз**:

```text
E   AssertionError: digit_sum({"n": -1}) -> -1, ожидалось исключение ValueError
```

Это расшифровывается так: тест вызвал `digit_sum(n=-1)`, функция вернула
`-1`, а должна была поднять `ValueError`. То есть для отрицательных чисел
ты забыл проверку:

```python
def digit_sum(n: int) -> int:
    if n < 0:
        raise ValueError("Число должно быть неотрицательным")
    ...
```

Другой частый вид:

```text
E   AssertionError: merge_sort({"items": [3, 1]}) -> [3, 1], ожидалось [1, 3]
```

Функция вернула не то (не отсортировала). Понятна конкретная пара
«вход → что получилось → что ожидалось» — по ней и правь код.

А ещё бывает:

```text
E   NotImplementedError
```

Значит функция в решении — **пустая заглушка** (ты ещё не написал тело,
см. следующий шаг).

## Шаг 6. Решать задачу

**Найди файл задачи.** Папка называется `solutions/<тема>_<номер>/`:

```text
solutions/recursion_33/recursion_33.py
```

Открой его в любом редакторе (VS Code, PyCharm, Блокнот):

```python
def digit_sum(n: int) -> int:
    """Сумма цифр неотрицательного целого числа."""
    raise NotImplementedError  # ← вместо этого пиши свой код
```

Заменяй `raise NotImplementedError` своим кодом. **Докстринг и сигнатуру
функции не удаляй** — тесты вызывают функцию именно с таким именем.

Сохрани файл и снова:

```bash
dsa-trainer run 33
```

Повторяй, пока не будет `passed`. Это и есть весь цикл работы: **пишу →
запускаю → читаю ошибку → правлю**.

### Хочешь решать «с нуля», а не дописывать готовое?

Готовые решения в репозитории лежат как эталоны. Преврати нужные задачи
в пустые заготовки:

```bash
python tools/make_todo.py 33 31 47
```

Скрипт сохранит копии (`*.py.bak`) и перепишет тела функций в
`raise NotImplementedError`. Решать так честнее.
Вернуть решение обратно — переименовать `.py.bak` в `.py`.

## Шаг 7. Смотреть прогресс

```bash
dsa-trainer stats
```

Печатает табличку по темам и общий процент:

```text
  Рекурсия                     [#####...............]  5/21

  Итого: 12/86 (14%)
```

Прогресс хранится в файле `.dsa_progress.json` и в git не попадает.
Сбросить: `dsa-trainer reset -y`.

Отдельно: **эталонные решения** («решение уже есть в репозитории»)
отмечаются как `[.]` — это не твой прогресс, просто подсказка, что в файле
уже лежит готовый код.

## Шаг 8. Запустить решение как программу

Каждая задача — самостоятельный файл с демо-примером:

```bash
python solutions/recursion_47/recursion_47.py
```

|---|---|
| `dsa-trainer list` | все задачи со статусами |

## Частые проблемы

| Сообщение | Причина и решение |
|---|---|
| `bash: cd: D:codesdsa-python-notes: No such file or directory` | в Git Bash путь через `\` ломается → пиши `/d/codes/dsa-python-notes` |
| `bash: dsa-trainer: command not found` | не сделал `pip install -e .` → используй `PYTHONPATH=src python -m dsa_trainer run 33` |
| `No module named dsa_trainer` | то же: либо `pip install -e .`, либо `export PYTHONPATH=src` (Git Bash) / `$env:PYTHONPATH="src"` (PowerShell) |
| `No module named pytest` | `pip install -r requirements-dev.txt` |
| `AssertionError: ... got NoneType` | функция ничего не вернула — проверь `return` |
| `NotImplementedError` | тело функции — заглушка, напиши код |
| `[SKIPPED]` | обычно нет Pillow: `pip install pillow`, но это необязательно |

## Дайджест: как это устроено внутри (необязательно)

- Решение задачи живёт в `solutions/<тема>_<номер>/<тема>_<номер>.py`.
- Тест задачи — `tests/test_<тема>_<номер>.py`; он сам импортирует
  решение и сравнивает результаты с ожидаемыми.
- Условие хранится в `src/dsa_trainer/catalog.json` и генерируется
  в читаемый вид в `docs/tasks.md`.
- Часть тестов проверяет **свойства** (например, что сортировка совпадает
  с `sorted()`), часть — конкретные пары вход/выход и ожидаемые исключения.
