# Участие в проекте

Спасибо, что хочешь помочь. Мелкие правки можно присылать сразу PR-ом,
крупные — обсуди через issue.

## Среда

```bash
python -m pip install -r requirements-dev.txt
python -m pip install -e .
pre-commit install
```

## Перед PR

```bash
ruff check . && ruff format --check .
pytest -q
python tools/build_catalog.py --check
```

## Новая задача

1. Номер задачи уникален: `id` в `src/dsa_trainer/catalog.json`.
2. Slug: `<тема>_<двузначный номер>`, например `files_31`.
3. Условие описывает **контракт функции**: имя, аргументы, что вернуть,
   какие исключения поднимать, чем отличаются краевые случаи.
4. В тестах важны не только «пример из условия», но и: пустой вход,
   отрицательные значения, отсутствие решений, неизменность аргументов.
5. Статус `todo` у задачи, которую оставляешь читателю; `solved` —
   когда решение готово.
6. После PR запусти `python tools/build_catalog.py --write` — `docs/tasks.md`
   должен обновиться в том же коммите.

## Стиль

- Python 3.10+, `from __future__ import annotations` не нужен, но `X | Y`
  в аннотациях допустим.
- Публичные функции — с докстрингом и аннотациями.
- Без глобального изменяемого состояния: параметры по умолчанию не должны
  быть списками/словарями.
- Для случайности в «продуктовом» коде — `secrets`; в тестах — seed через
  `random.Random`.
